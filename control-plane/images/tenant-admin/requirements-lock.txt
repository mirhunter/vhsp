# Exact dependency versions this image is built and tested against --
# generated via `pip freeze` against a clean install of the package list
# below, on the same python:3.12-alpine base this Dockerfile uses. A
# follow-up security review flagged that the Dockerfile's bare
# `pip install flask passlib fido2 ...` (no version pins, no lock file)
# meant every image rebuild could silently pull different, newer
# versions of every dependency -- including fido2 (this container's
# entire WebAuthn/second-factor implementation) and pymysql (the SQL
# console's transport) -- with no signal that anything changed. Same
# "pinned lock file separate from loose dev floors" posture as the
# control-plane's own top-level requirements-lock.txt.
#
# Regenerate after intentionally upgrading a dependency:
#   docker run --rm python:3.12-alpine sh -c \
#     "pip install --no-cache-dir flask passlib fido2 pymysql pyotp qrcode gunicorn >/dev/null && pip freeze"
# and re-verify the image still builds and the app still starts before
# committing the new pins.
